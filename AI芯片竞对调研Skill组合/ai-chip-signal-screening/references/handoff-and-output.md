# 成果与交接规则

## 存储与编号

用户指定输出位置优先。默认以竞对看板目录的上一级为组合根目录，创建 `成果/初筛/YYYY-MM-DD/筛选报告.md`。本工作区为 `AI芯片竞对调研Skill组合/成果/初筛/`；若任务工作区已经是组合目录，直接使用其 `成果/`，不重复嵌套组合目录。结合当前任务及适用 `AGENTS.md` 确定组合位置；无法可靠定位时先明确，不能用 Skill 安装目录代替。不写入技能目录，不额外嵌套 `runs/`。日期按Asia/Shanghai，同日用 `-02`、`-03` 后缀。仅实际运行后生成报告，不预填产品或虚构结果。

新候选编号如 `2026-10-20-S01`、`2026-10-20-02-S01`，序号仅在批次内递增；同一事件后续沿用原编号，旧版编号也保留。不得覆盖旧扫描结论，可在末尾追加人工决定或实际研究结果。报告间采用相对路径回链；交付给用户时给出实际完整文件路径。迁移目录不改变批次或候选编号。

## 单份报告

正文以便于人工选择为目标，通常约一页；候选较多时完整保留重要项，不为篇幅截断。依次包含：

1. **本轮概述**：批次、截止时间、实际窗口和厂商、是否有可用基线，以及主要变化与推荐编号。
2. **六列候选表**：按下表填写短句，来源直接给可点击原文链接。
3. **历史待处理项**：尚未决定的重要候选，保留原编号、一句摘要及最近相关报告链接；本轮已展开的项不重复列。
4. **八家覆盖**：各家实际窗口、结果、最近有效完成截止时间及批次、影响结论的主题或访问缺口。

| 列名 | 内容 |
| --- | --- |
| 候选编号 | 新编号或同事件原编号 |
| 厂商／产品 | 型号不明时保留原产品线称谓 |
| 线索与变化 | 发生什么、相比已知内容新增什么；已知事件日期随文注明 |
| 深挖建议与理由 | 建议深挖、保留观察或本轮无需深挖，附具体理由 |
| 来源与访问情况 | 来源名称、可点击原文链接、已知发布日期、身份与实际访问情况；多来源分别说明 |
| 待核实问题 | 第二阶段能继续解决的具体问题 |

长文档、图表、视频必要时在来源旁注明页码／图号／时间点。摘要不能当正文，官方宣称不能当独立测评。未知留空或说明。普通旧闻和转载直接合并或排除，无需逐篇建表；无新增时说明实际已查范围。

普通报告不附查询表达式、全部访问URL、重试／操作记录、用量统计或独立证据表，也不另建日志和状态文件。成本汇总仅在用户询问时提供，详细过程仅在明确要求测试诊断时展开。影响结论的缺口仍须在相关候选或覆盖表注明。

## 增量与历史

最近报告的覆盖表逐家延续有依据的有效完成日期，未扫描厂商不写当前日期。完成扫描指技术与商业基础方向已执行，并已判断、处理或明确注明活动／媒体补查范围；不得声称所有方向都做过查询。单页正文受限不抹掉已完成扫描；检索方向未执行、工具不可用或仅查特定型号时，记录部分／受限／聚焦扫描，沿用此前全主题完成日期。

已由人工观察、跳过或已交接的历史项，无实质新证据时不重复催促。有补充、更正、冲突或撤回时沿用原编号，在新报告说明前后差异和此前决定，保留旧结论。独立新事件另编号关联。

先读最近报告，再定向定位相关历史和最新决定；不以最近报告没列出就判断首次发生。旧CSV、简报、日志和台账只读参考，保留旧编号和重要未处理线索，不继续维护旧格式。

## 人工决定与接力

用户选择全部、部分或零项。人工决定按实际时间、候选编号和原意追加到对应报告末尾，最新明确指示优先；未决定时不生成默认选择。

“本轮不深挖”表示暂缓，只有明确不再关注才记跳过。模型建议不能覆盖人工决定。“收到”或沉默不能触发第二阶段。

交接提供“筛选报告路径＋候选编号＋指定研究范围”。若当轮已有可核的原文片段，可连同来源URL、读取时间和定位共享，供第二阶段和授权代理复用；仅有筛选摘要不够。内部共享不要求另建正式交接或过程文件。

第二阶段保存并检查研究成果后，按实际发生在原报告追加研究范围、核心观察及结果链接，必要时补充后续关注点；不设置研究完成度字段。选择不等于已开展研究，第二阶段不可用时说明情况，不声称启动。跨会话需明确路径，不主动发消息到其他会话。

## 保存前检查

核对编号、六列、来源链接、日期、访问描述、去重与历史延续，确保重要未初查线索仍可见，覆盖时间有实际依据，人工决定及回链按实际发生记录。只交付本轮单份筛选报告。

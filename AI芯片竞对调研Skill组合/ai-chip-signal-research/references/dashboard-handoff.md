# 长期看板收录

本工作区的深挖报告保存并检查后、完成第一阶段回链后，自动更新固定竞对看板，无需用户再次要求。无第一阶段报告或无法回写时，仍可在如实说明后收录实际研究成果。只读取本地报告，不重新联网检索或改写研究结论，不由更新看板触发新研究。

## 执行

使用本 Skill 附带的脚本，传入本轮实际报告路径；存在来源筛选报告时一并指定。参数使用真实绝对路径并正确引用，不能照抄占位符：

```text
node "<本Skill绝对路径>/scripts/update-dashboard.cjs" --report "<本轮深挖报告绝对路径>" --screening "<来源筛选报告绝对路径>"
```

没有第一阶段报告时省略 `--screening`。自定义输出目录也必须传入 `--report`，脚本会持续登记该报告供之后核对。无需迁移或复制原报告。

脚本从 Skill、当前工作目录及报告路径的上级查找 `AI芯片竞对调研Skill组合/看板/`，不搜索其他磁盘目录。外部安装、目录结构不同或存在多个看板时，显式增加 `--dashboard "<看板目录绝对路径>"`；也可使用已有的 `AI_CHIP_DASHBOARD_DIR` 环境变量。不擅自修改用户全局环境。

本工作区默认报告位置为 `AI芯片竞对调研Skill组合/成果/深挖/YYYY-MM-DD/深挖报告.md` 和 `AI芯片竞对调研Skill组合/成果/初筛/YYYY-MM-DD/筛选报告.md`，相对工作区根目录。成果目录与看板同属竞对组合；若工作区已经是组合目录，直接使用其中的 `成果/`，不重复嵌套。看板默认扫描这两处，自定义位置仍用 `--report` 登记。路径迁移应同步核对回链并追加看板 `reportRelocations` 映射，保留已有映射链，使索引原位更新，不将仅路径变化计作新研究版本。

## 报告兼容要求

沿用单份 Markdown 报告。开头明确研究批次、含时间的资料截至时间及 Asia/Shanghai 口径。观察概览表提供研究编号、候选编号和核心观察，不设置完成度字段；逐项信息与分析的章节标题含对应研究编号，后续关注点按需提供。支持完整编号及明确批次下的 `R01`／`S01` 简写。旧版结论概览和完成度列仅作兼容读取，不作为新报告要求。

无第一阶段编号的独立研究，在概览候选编号处记“无”，并在逐候选标题开头明确八家之一的厂商，如 `R01：华为／具体产品与问题`。避免仅靠正文提及多个厂商猜测归属。

后续重研同一候选时沿用完整候选编号、分配新研究编号；这是将新研究归入同一事件历史的依据。不同编号不能仅凭标题相似自动合并；确需关联时，在看板 `config.json` 的 `eventGroups` 中写明候选编号、共同事件 ID 和依据。

## 核对与失败处理

检查命令的退出状态、输出看板路径、研究版本数及 `pending`。仅退出为 0 且没有待处理项时，说明看板已成功更新；交付时简述收录结果并给固定看板链接，不在研究报告额外增加操作日志。

市场观察不以官方证明材料是否齐全作为收录门槛，看板不展示研究完成度。历史报告保留原文，完整原报告中旧措辞仍可见；普通看板不展示旧完成度标签，也不据此改写原有信息或分析。报告提取失败、来源路径缺失或看板不可用时，保留报告并明确“报告已保存，看板收录未完成”，说明实际原因。修复后使用同一命令补录，或运行看板的 `scripts/build-dashboard.cjs --rebuild`；重复运行不会重复新增。

看板索引和 HTML 是集中维护的派生文件，不是每轮新增的研究报告、证据表或过程日志。无需常驻进程、定时任务或数据库。页面已打开时，更新后刷新可见。

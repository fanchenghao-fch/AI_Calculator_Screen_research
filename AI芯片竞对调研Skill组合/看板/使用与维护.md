# 竞对厂商信息汇总 · 使用与维护

打开本目录的 **竞对看板.html** 即可使用，无需联网或启动服务器。页面内的原报告和历史版本已嵌入；点击外部证据链接时需要联网。深挖技能更新文件后，已打开的页面刷新即可看到新成果。

## 正常更新

本工作区深挖技能已增加自动收录步骤：保存并检查报告、完成筛选记录回链后，调用技能的 `scripts/update-dashboard.cjs`。用户自定义的报告输出路径也会登记并持续核对。报告定位为附来源的市场观察，不设置研究完成度；看板不会重新检索或生成研究结论。

本地维护的技能入口为工作区 `.agents/skills/ai-chip-signal-research/`；报告归档到竞对组合内的 `成果/深挖/YYYY-MM-DD/深挖报告.md` 和 `成果/初筛/YYYY-MM-DD/筛选报告.md`，与本看板目录相邻。本工作区完整相对位置为 `AI芯片竞对调研Skill组合/成果/`；若工作区已是组合目录，直接使用其中的 `成果/`，不重复嵌套组合目录。组合目录中的技能副本也遵循同一规则。

## 补录、核对和重建

在 macOS 上可双击本目录的 **更新看板.command**，查看收录结果后刷新看板。也可直接在 Codex 中提出“核对并更新竞对看板”。

在本目录执行以下命令核对所有已配置目录和已登记报告，重复运行不会重复收录：

```sh
node scripts/build-dashboard.cjs --rebuild
```

新增位于其他位置的报告：

```sh
node scripts/build-dashboard.cjs --report "/实际路径/深挖报告.md"
```

若来源筛选报告已搬迁、或旧报告没有可用回链，可再传 `--screening "/实际路径/筛选报告.md"`。单次指定来源筛选报告时只搭配一份 `--report`。所有占位路径都应替换成真实路径。

命令输出 `pending: 0` 且退出为 0，才表示本轮收录全部完成。若存在待处理项，页面底部显示“收录待核对”入口；已收录研究继续保留。修复相应报告、格式或路径后重新执行，即可补录。页面或索引损坏时先保留副本，再排查，不能直接清空已有历史。

## 维护文件

- `config.json`：扫描目录、人工明确的事件关联及 `reportRelocations` 路径迁移映射。扫描目录相对本看板，迁移的 `from` 和 `to` 相对工作区根目录；工作区整体搬迁后仍可重建。不要删除仍用于历史索引或旧报告回链的迁移映射。
- `data/index.json`：自动索引，含报告原文快照、路径、研究版本及外部报告登记。它也是已经缺失或被修订的历史报告快照的恢复依据，需与原报告一同备份，不应手工删改。
- `src/`：页面、样式和阅读交互源码。修改后重新构建，不直接修改生成页面。
- `scripts/`：报告提取和构建程序，仅使用本地 Node.js 内置模块，不需安装依赖。
- `vendor/`：离线 Markdown 解析程序及其 MIT 许可。
- `竞对看板.html`：固定使用入口，可单独复制用于阅读；要继续维护，应保留整个工作区和索引。

现有历史成果位于看板上一级的 `成果/`，原批次编号和历史测试标识保留。看板扫描 `../成果/深挖/`、`../成果/初筛/`；原先工作区根目录下的成果路径通过迁移映射兼容。报告正文不作事实再核验，核查日期仍以各原报告为准。目录迁移及回链调整原位更新索引，不新增研究版本。

## 历史与归属

同一候选的后续研究沿用完整候选编号并分配新研究编号，自动形成版本历史。相同内容的报告副本不重复收录；原报告内容修改后保留之前的快照。来源暂时缺失时不删除历史，恢复后重新核对。

不同候选编号不会仅凭标题或正文关键词自动合并。已经明确是同一事件时，可在 `config.json` 的 `eventGroups` 中添加：

```json
{
  "id": "人工确认的共同事件ID",
  "candidateIds": ["2026-10-23-S01", "2026-10-24-S02"],
  "reason": "关联依据及对应报告位置"
}
```

一个候选只能属于一个事件组，组内厂商必须一致。日期排序按研究核查截止，重复导入或构建时间不会把旧事件推到最前。

## 备份与异常恢复

备份原始报告、`data/index.json`、`config.json` 及页面源码即可保留维护能力。单独保存 HTML 仅能阅读，无法恢复全部维护状态。

更新先生成临时文件，通过脚本语法和数据检查后再替换固定索引和页面。失败时报告与旧页面保留。若更新进程异常终止留下 `.build.lock`，先核对其中的进程信息，确认该进程已结束，再移除该锁目录并重试。

报告识别以观察概览表、研究编号和候选章节为依据，支持没有完成度字段、没有后续关注点章节的新报告，也兼容旧版结论概览。普通看板不展示完成度标签，旧字段中有价值的限定按原内容保留为观察补充；打开完整历史原报告时，仍可看到原来的完成度文字。历史原文不因展示规则变化而被改写，也不会新增研究版本。

未来报告结构变化时，应更新提取程序并运行 `node --test tests/maintenance.test.cjs`，再重新生成看板；不能为适配页面而改写旧研究结论。
